# 자료 캐기 (research)

- 차례 다섯. 첫 전달문 (「데이터 첫 보기」) 은 1 과 2 만으로 20분 안에 보고하고, 그 뒤는 끝내지 않는다
  1. 자료 지도: 파일마다 이름, 행 수, 열 이름과 뜻 (README 의 열 설명을 옮기고 모르면 「뜻 모름」), 파일 사이의 참조 (어느 열이 어느 파일의 ID 를 가리키나)
  2. 표본 20줄과 열 설명: 파일마다 앞 20줄을 그대로 (사람이 원자료의 꼴을 본다). 값의 범위, 날짜 꼴, 빈 값 표시
  3. 분포와 결측과 중복과 이상값: 열마다 빈 값 수, 중복 ID, 범위 밖 값, 참조가 안 맞는 ID. 숫자는 코드로 재고 명령을 적는다 (규칙 7)
  4. README 의 규칙과 어긋나는 값: 운영 규칙 (요구.md) 을 데이터에 대 보고 어긋나는 줄을 찾는다 (예: 한도를 넘는 날, 담당자가 있는데 기록이 없는 줄)
  5. 발견 쌓기: `research/발견.md` 에 「발견 N: 한 줄 결론 / 근거: 파일, 줄 번호, 값 그대로 / 뜻: 요구나 합의문의 어디에 걸리나 / 담당자에게 물을 것」. 새 발견이 있으면 `../h done` 으로 메인에 알린다 (같은 번호로 다시 보고하면 _2)
- 발견마다 원자료 줄 번호와 값 몇 줄을 그대로 붙인다. 요약만 믿지 않게 한다
- 과제가 변경 데이터셋과 오류 데이터셋을 요구하면 (「정상적으로 바뀐 묶음」, 「잘못된 입력이 든 묶음」) research 팀원이 만든다: 원본에서 고친 줄과 까닭을 적은 생성 코드 (`make_datasets.py`) 와 묶음 폴더. 오류 묶음은 요구가 든 오류 종류 (열 누락, 없는 ID 참조, 형식 오류) 를 하나씩 따로 둔다
- 바깥 자산: 담당자가 속한 회사의 공개 자료에서 색 (대표색 둘), 글꼴 이름, 글자 로고 꼴을 찾아 product 에 넘길 `자산.md` 를 쓴다. 그림 파일은 받지 않는다 (상표). 없으면 「중립 스타일」 이라고 적는다
- 팀원이 있으면 팀장이 나눈다 (예: research_1 데이터 품질, research_2 변경과 오류 묶음, research_3 바깥 자산). 팀장이 발견을 모아 번호를 하나로 매긴다
- 보고의 「결정」 칸에 데이터에서 나온 권유 (예: 「필수: 날짜 열은 문자열로 읽는다, 섞인 꼴이 있다」) 를 적는다. 확정은 메인과 사람
