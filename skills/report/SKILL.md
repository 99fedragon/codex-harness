# 제출 문서

- 과제가 정한 파일과 양식이 먼저다. 요구.md 의 「제출 파일과 양식」 에 적힌 이름과 칸을 그대로 쓴다. 양식에 없는 칸을 만들지 않고, 해당 없는 칸은 「해당 없음」. 과제가 준 README 는 고치지 않는다
- 정하지 않았을 때만 보고서.md 네 칸 (실행법, 판단과 근거, 검증 결과, 남은 한계). 칸마다 세 줄에서 여덟 줄, 개조식. 처음 보는 사람이 읽는다
- 실행법: 명령을 그대로 (python 경로, 인자, 포트, 걸리는 시간). 새 터미널에서 그대로 쳐서 같은 결과가 나와야 한다. 상대 경로로. 역할이 둘이면 각각 들어가 보는 법
- 판단과 근거: 결정.md 의 번호를 인용해 고른 것과 버린 것을 짝으로. 근거는 숫자나 담당자 말 (대화.md 에서 그대로). 핵심 방법은 더 단순한 안과 더 강한 안을 함께 적고 지금 수준을 고른 까닭과 감수한 비용
- 구현 범위와 검증 결과: 요구.md 의 번호마다 한 줄 (요구 → 됨, 안 함 (까닭), 가정 → 시험 파일과 명령 → 결과 숫자). 못 한 것도 적는다
- 남은 한계: 약점마다 지점 (파일:함수), 깨지는 조건, 파급, 다음에 할 것
- 판단과 경험을 서술하는 칸 (예: 「가장 까다로웠던 문제와 해결」, 「AI 와 함께 푼 사례」) 은 문장을 바로 쓰지 않는다. 결정.md 의 사례에서 사례 후보 셋을 표 (사례, 한 줄, 근거: 발견과 확인 명령, 사람이 받아들이거나 고치거나 버린 것) 로 보이고 사람이 고른 뒤 그 사례만 쓴다. 사람이 겪지 않은 사례는 쓰지 않는다
- 「초안」, 「에이전트」, 「검토 예정」 같은 작업 메모를 제출 문서에 남기지 않는다
- 표는 열 다섯까지. 그림은 파일로 두고 경로를 적는다
- 넘기기 전: 실행법을 새 터미널에서 한 번 그대로 돌린다. 숫자와 파일 이름이 코드와 같은지 본다 (규칙 7). 제출 파일 목록을 요구.md 와 대조한다
