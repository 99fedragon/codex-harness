# 검토 (verify)

- 판정의 근거: 전달문의 끝난 조건, 합의문 (성공 기준 숫자, 만들 것, 제약), 대화.md 의 담당자 요구. 보고는 돌리는 법 (실행법) 만 참고한다. 보고의 검증 결과는 자기 판정을 낸 뒤에 견준다
- 1 끝난 조건과 합의문의 요구를 번호 붙여 목록으로
- 2 결과물을 `검토<번호>/` 로 복사해 직접 돌린다. 실행법이 없거나 안 돌면 코드에서 돌리는 길을 찾는다. 남의 폴더에서 돌리지 않는다
- 3 조건마다 시험 → 결과 숫자. 값은 코드로 잰다 (규칙 7). 못 돌린 것은 「확인 못 함: 까닭」
- 4 빈틈 훑기 (짧게, 셋까지): 요구 가운데 빠진 기능, 보안 (입력 검사, 스크립트 삽입, 명령과 경로 삽입, 비밀 값이 코드에 있음, 오류에 내부 정보가 드러남), 빈 값과 잘못된 입력에서의 동작. 웹이면 실제로 요청을 보내 본다. 빈틈마다 무거움과 가벼움을 가른다
- 5 밖 쓰기: trace 의 꼬리표를 본다. 「쓰기 명령 있음」 은 조각을 보고 정말 그 파일에 썼는지 가른다. 「읽기만 보임」 과 「기록에 없음」 은 다른 세션이 바꾼 것일 수 있다
- 6 개인정보: 합의문 제약에 개인정보가 있으면 privacy 스킬 기준으로 결과물과 보고와 로그에 원본 값이 남았는지 코드로 찾는다
- 7 보고와 견주기: 보고가 말한 결과와 직접 잰 결과가 다르면 「보고와 실제가 다름」
- 판정: 끝난 조건 하나라도 실패, 보고와 실제가 다름, 무거운 빈틈 (보안 구멍, 합의문의 핵심 요구 빠짐), 밖에 쓴 증거, 원본 개인정보가 남음, 돌려 보지 못함 가운데 하나라도 있으면 「이상 있음」. 가벼운 빈틈은 「빈틈」 줄에 적기만 한다
- 지킬 것: 쓰기는 `검토<번호>/` 안에서만. 남의 폴더와 루트 문서를 고치지 않는다 (알리기만). h 명령은 쓰지 않는다 (판정은 답으로만). 웹 서버를 띄우면 포트는 18000 + 번호 (verify 탭의 심층 검증은 19000 + 번호), 끝내기 전에 끈다. 15분 안에

마지막 답의 꼴 (첫 줄이 판정. 「이상 없음」 이나 「이상 있음: 까닭 한 줄」 만):

```text
이상 있음: 입력 칸에 스크립트를 넣으면 그대로 실행됨 (보안)
조건: 1 통과 (명령, 결과) / 2 실패 (명령, 결과)
빈틈: 무거움 1 (스크립트 삽입) / 가벼움 1 (빈 입력에 안내 없음)
보고와 다른 곳: 없음
밖 쓰기: 없음 / 개인정보: 해당 없음
돌린 명령: …
```
