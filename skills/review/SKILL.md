# 검토 (verify, 읽기만)

- 결과물을 돌리지 않는다: 서버를 띄우거나 시험을 새로 짜지 않는다. 시험 결과는 h 가 붙인 「시험:」 줄 (h 가 done 때 팀장의 run_tests.sh 를 돌린 결과) 을 쓴다. 5분 안에
- 판정의 근거: 전달문의 끝난 조건, 합의문 (성공 기준 숫자, 만들 것, 제약), 요구.md, 대화.md 의 담당자 요구
- 앞뒤: 요구.md 의 「안 함」 과 「가정」 이 대화.md 보다 앞선다. 합의문이 「상태: 초안」 이면 대화의 요구로 판정하지 않는다 (끝난 조건과 요구.md 로)
- 읽는 것: 바뀐 코드 (h 가 준 git diff 범위, 없으면 그 세션 폴더), 보고, 전달문, 피드백.md, 밖 변경 추적 (trace)
- 보는 것 (읽기만, 빈틈은 셋까지 짧게)
  - 1 빠진 요구: 요구 번호는 있는데 코드도 시험도 없는 것
  - 2 요구 밖 기능: 요구.md 와 합의문에 없는 동작 (범위 넘침)
  - 3 잘못 구현된 것: 요구 줄과 코드가 다른 곳 (요구 줄을 인용)
  - 4 시험이 요구를 재는지: 기대값을 코드와 같은 식으로 다시 계산한 시험, 아무것도 확인하지 않는 시험, 시험이 없는 요구 번호
  - 5 F번호 (루트 피드백.md 의 번호) 가 있으면 판정 아래 「확인: F3 근거 있음 (시험 이름), F5 근거 없음 (까닭)」
  - 6 밖 쓰기: trace 의 꼬리표. 「쓰기 명령 있음」 은 조각을 보고 정말 그 파일에 썼는지 가른다. 「읽기만 보임」 과 「기록에 없음」 은 다른 세션이 바꾼 것일 수 있다
  - 7 개인정보: 합의문 제약에 있으면 privacy 스킬 기준으로 결과물과 보고와 로그에 원본 값이 남았는지
  - 8 보안 (읽기만): 비밀 값이 코드에 있음, 사람이 넣은 글을 그대로 HTML 로 (스크립트 삽입), SQL 이나 명령을 글 이어 붙이기로, 오류에 내부 정보. 웹이면 새 창을 여는 코드 (window.open, target=_blank, alert, confirm)
- 보고와 견주기: 보고가 말한 것 (기능, 시험 결과) 과 코드나 「시험:」 줄이 다르면 「보고와 실제가 다름」
- 판정: 「시험: 실패」 나 「시간 넘김」, 핵심 요구 빠짐, 무거운 보안 구멍, 밖에 쓴 증거, 원본 개인정보, 보고와 실제가 다름 가운데 하나라도 있으면 「이상 있음」. 가벼운 빈틈은 「빈틈」 줄에 적기만 한다
- 지킬 것: 쓰기는 `검토<번호>/` 안에서만. 남의 폴더와 루트 문서를 고치지 않는다 (알리기만). h 명령은 쓰지 않는다 (판정은 답으로만)

마지막 답의 꼴 (첫 줄이 판정. 「이상 없음」 이나 「이상 있음: 까닭 한 줄」 만):

```text
이상 있음: 요구 R3 의 「실패하면 기존 데이터 유지」 가 코드에 없음
시험: 통과 12/12 (h)
요구: R1 app.py:create 와 test_r1 / R3 코드 없음
빈틈: 무거움 1 (…) / 가벼움 1 (…)
보고와 다른 곳: 없음
밖 쓰기: 없음 / 개인정보: 해당 없음
```
