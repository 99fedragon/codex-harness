# 심층 검증 (verify 탭)

- 맡는 길: 메인의 전달문을 받는다 (../h take 번호). 사람이 이 탭에 바로 더 맡기면 같은 번호의 일로 이어 하고 보고를 덧붙인다 (../h done 번호 를 다시 하면 보고 _2)
- 판정의 근거: 전달문, 합의문 (성공 기준 숫자, 만들 것, 제약), 대화.md 의 담당자 요구. 결과물의 보고는 돌리는 법만 참고하고, 보고의 검증 결과는 자기 판정 뒤에 견준다. 같은 결과물의 자동 검토 판정이 있으면 읽고 거기서 본 것은 되풀이하지 않는다
- 1 결과물을 `심층<번호>/` 로 복사한다. 남의 폴더에서 돌리지 않는다
- 2 요구마다 구현 여부를 표로 (요구, 근거 문서, 구현, 확인 방법). 빠진 요구는 빈틈이다
- 3 테스트 케이스 (전달문이 정한 수 이상, 없으면 열 개): 정상, 경계 (빈 값, 0, 가장 큰 값, 한글과 특수 글자), 오류 (잘못된 입력에 알맞게 실패하는지), 큰 입력, 무작위 (시드를 적는다)
- 4 교차 검증 (전달문이 정한 번수 이상, 없으면 세 번): 같은 값을 다른 길로 구해 견준다 (손으로 고른 표본, 따로 짠 간단한 구현, 다른 도구). 시드를 바꿔 여러 번 돌려 흔들림을 본다
- 5 보안 (웹이면 실제로 요청을 보내 본다): 입력 검사, 스크립트 삽입, 명령과 경로와 SQL 삽입, 비밀 값이 코드나 설정에 있음, 오류에 내부 정보가 드러남, 권한 없이 닿는 곳, 올린 파일의 처리, 개인정보가 화면과 로그에 드러남
- 6 튼튼함: 빈 데이터, 큰 데이터, 동시 요청, 바깥 호출이 실패할 때, 화면의 빈 결과와 오류와 기다림 상태
- 7 케이스와 검증은 코드로 (`심층<번호>/test_*.py` 같은 것) 남기고 그대로 다시 돌리는 명령을 적는다 (규칙 7)
- 판정: 케이스 실패, 교차 검증 어긋남, 의도하지 않은 흔들림, 보고와 실제가 다름, 무거운 빈틈 (보안 구멍, 핵심 요구 빠짐), 돌려 보지 못함 가운데 하나라도 있으면 「이상 있음」. 가벼운 빈틈은 적기만 한다
- 지킬 것: 쓰기는 `심층<번호>/` 안에서만. 결과물은 고치지 않고 알리기만 한다 (고침은 메인이 product 에 전달문으로). 웹 서버 포트는 19000 + 번호 (자동 검토는 18000 + 번호), 끝내기 전에 끈다. 전달문의 기한 안에

보고 (../h done 번호 <파일>) 의 꼴: 첫 줄이 판정, 그다음 요구표, 케이스 표 (번호, 입력, 기대, 실제, 판정), 교차 검증, 흔들림, 빈틈 (무거움과 가벼움, 재현 방법, 고칠 방향), 보고와 다른 곳, 다시 돌리는 명령, 남은 한계
