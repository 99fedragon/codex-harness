# 하네스 다시 짜기

메인만 쓴다. 바뀐 상황(과제 꼴, 담당자 유무, 산출물, 시간, 데이터 크기)을 요구사항 한 줄씩으로 적고, 아래 표에서 바꿀 것만 고른다. 결정은 사람에게 묻고, 고친 뒤에는 바뀐 줄만 보여 준다.

## 바꿀 수 있는 것

| 상황 | 바꾸는 것 |
|---|---|
| 담당자(메신저)가 없고 README 가 전부 | 규칙 10 의 「대화」 는 README 의 요구사항을 대화.md 분야별에 옮기는 것으로 |
| 조사가 필요 없음 (데이터와 요구가 분명) | research 를 빼고 세션 셋. 규칙 1 과 3 의 이름 목록에서 지운다 |
| 산출물이 둘 이상 (예: 앱과 보고서) | product 를 product_app, product_report 로 나눈다. 새 폴더에 AGENTS.md (역할) 와 delivery/main/in_, out_, main/delivery/새이름/in_, out_. h 는 delivery/main 이 있는 폴더를 세션으로 안다 |
| 제출물 이름이 정해져 있음 | 규칙 6 의 보고서.md 를 그 이름으로. 네 칸은 유지 |
| 시작이 늦음 | 규칙은 그대로. 사람이 동결을 그만큼 늦춰 친다 (규칙 8) |
| 원본 데이터가 큼 | 규칙 3 에 「원본은 복사하지 않고 경로로 읽는다」 |
| 산출물 꼴이 정해짐 | 규칙 12 의 스킬 이름 하나를 전달문에 적는다 (report, webapp, page, app, pptx) |

## 안 바꾸는 것

- 결정은 사람 (규칙 1), 쓰기는 자기 폴더만 (규칙 3), 전달문 번호와 이름 끝 (규칙 4, h), 값은 코드로 (규칙 7), 저장 (규칙 9), 금지 (규칙 13)

## 절차

1. 요구사항을 한 줄씩 적고 위 표에서 바꿀 것을 고른다. 사람에게 보여 주고 결정을 받는다
2. AGENTS.md 의 줄을 고친다 (번호는 유지, 지운 줄은 「(없음)」 으로). 폴더를 더하거나 비운다 (있던 파일은 지우지 않는다)
3. STATE.md 의 결정과 까닭에 적는다
4. 사람에게 알린다: 「외주 세션마다 역할 이름을 다시 쳐 주세요」 (규칙 2 로 AGENTS.md 를 다시 읽는다). 새 세션은 `codex -C 새이름 새이름` (또는 `./go 새이름`) 으로 연다
