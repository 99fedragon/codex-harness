# 한마디와 하는 일

| 한마디 | 메인이 하는 일 |
|---|---|
| 「시작」 | 0 STATE.md 에 「시작 HH:MM」 (`./h now`). 1 README 와 과제 파일로 요구.md 를 채우고 답에 표를 통째로 보인다. 2 파일 주인 표: main/처음_파일.md 와 제출 파일마다 「누가 쓰나, 어느 수준 (양식 그대로 / 코드에서 / 사람이 고른 뒤)」 을 보이고 사람이 정한다. 3 전달문 초안 둘: research 「데이터 첫 보기」 (research 스킬 1, 2), product 「뼈대 점검」 (웹이면 뼈대를 product/app 으로 복사해 미리보기 로그인 확인, 아니면 실행 환경 점검). 「보낼까요?」 로 멈추고 「보내」 뒤 `./h send`, 번호 알림, `./h note` |
| 「요구 표」 | 요구.md 를 보여 준다 |
| 「담당자 질문」 | 요구.md 의 빈칸과 research 의 발견으로 물을 것을 고른다. 큰 틀 보냄 여부는 main/delivery/product/out_/전달문*_큰_틀* 유무로. 없으면 product 에 「큰 틀」 (webapp 스킬. 웹이 아니면 골격과 시험) 초안: 빈칸에 안 걸리는 요구 번호 전부, 빈칸은 자리만, README 밖 없음, 끝난 조건 (핵심 흐름 한 바퀴, 번호마다 시험), 뼈대 점검 뒤에. 「보낼까요?」. 물을 것은 한 덩이: 번호 단 질문만 text 블록 하나에, 기본안은 블록 밖 아래와 파일에 |
| 「합의문」 | 요구.md 와 대화.md 로 합의문 글을 답으로. 파일은 `./h note` 로 서기에 |
| 「대화」, 「모르는 곳」, 「범위 확인」 | `./h dialog` → `./h inbox` → define 스킬대로 답만 (모르는 곳 표, 구현 범위 확인 글, 확정). 곁 파일은 만들지 않는다. 정리는 답 끝의 `./h note` |
| 「집중 product」 | 그 뒤 product 보고마다 요구.md 와 합의문에 견줘 「문제 없음」 이나 「피드백 F번호: …」 를 피드백.md 에, 설명.md 갱신 (결정.md 는 h note). 새 전달문 없음. 피드백이면 「product 창에 칠 말: F3 고쳐」 |
| 「집중 해제」 | 기본으로 |
| 「동결」 | 새 기능 없이 고침과 제출 문서만 (규칙 8, report) |
| 「설명」 | explain 스킬로 설명.md |
| 「최종 점검」 | deepcheck 스킬대로 |

# 턴마다 (서기)

- 사람 말을 받으면 맨 먼저 `./h inbox`. 답 끝에 `./h note <정해진 것, 새 번호 R·U·D, 단계>` (서기가 기록 다섯을 뒤에서 고친다. 메인은 안 쓴다). 「저장」 은 `./h note --wait`

# 전달문 허가

- 전달문은 바로 보내지 않는다. 본문을 main/초안/ 에 쓰고 한 건에 두 줄 (목적) 로 보이며 「보낼까요?」 로 멈춘다. 「보내」, 「1 보내」, 「2 고쳐: …」 뒤에만 `./h send`

```text
보낼 것 (초안 2): 1 research 「데이터 첫 보기」 목적: … / 2 product 「뼈대 점검」 목적: …
보낼까요? (「보내」, 「1 보내」, 「2 고쳐: …」)
```

# 상위 결정과 논의 글

- 상위 결정은 메인이 정하지 않고 사람에게 묻는다: 핵심 아이템 (무엇을 만들 것인가), 만들 것과 안 만들 것, 핵심 방법 (최적화 기준, 판단을 코드와 LLM 에 나누는 경계), 집중 모드 전환, 동결, 제출 문서에 실을 사례. 가르는 기준은 「결과물의 꼴이나 범위가 바뀌는가」
- 논의 글의 꼴 (짧게, 한 번에 하나): 정할 것 / 선택지 A, B (, C) / 득실 / 추천과 까닭 (담당자 말이나 요구 번호) / 팀 권유 (보고의 결정 칸, 없으면 없음)

- 사람의 답 「A」, 「B 로, 까닭은 …」, 「더 물을 것: …」. 정해지면 D번호를 매겨 한 줄로 알리고 h note 로 서기에 (내용, 버린 안, 까닭은 사람 말 그대로, 감수한 비용, 누가)
- 팀의 보고에 「결정」 칸이 있으면: 「필수:」 는 결정.md 에 「누가: 팀장 이름」 으로 바로 적고 진행, 나머지 권유는 결과물의 꼴이나 범위가 바뀌면 논의 글로, 아니면 결정.md 에 적기만
- 같은 번호가 두 번 「이상 있음」 이면 고침 대신 논의 글로

# 하네스 다시 짜기 (「하네스」 뒤에 바뀐 상황)

바뀐 상황을 한 줄씩 적고 사용법.md 「상황이 바뀌면」 표에서 바꿀 것만 골라 사람의 결정을 받는다. 안 바꾸는 것: 결정은 사람 (1), 쓰기 (3), 번호 (4), 코드로 재기 (7), 금지 (13). AGENTS.md 의 줄을 고치고 (번호 유지, 지운 줄은 「(없음)」) h note 로 적은 뒤 「역할 이름을 다시 쳐 주세요」 (규칙 2)
